# P0.3 — E2M1/NVFP4 scaled-MMA probe on GB10 (sm_121): result + 3-voice review

**Probe:** `examples/scaled_mma_probe.rs` (Codex-written, Codex-fixed). **Result on the real GB10:**
`DEVICE_REPORTS_SCALED_MMA: true` / `LAUNCH: OK` / `NUMERICS: max_abs_diff=0.000000 PASS` (non-symmetric values).
Config: `e2m1x2 × e2m1x2 → f32`, `e4m3` scales, m16n8k64, scales_factor 4, via
`cmma::MmaDefinition::<e2m1x2,e2m1x2,f32>::new_scaled::<e4m3>(16,8,64,4)`. Emitted PTX (Opus-traced):
`mma.sync.aligned.kind::mxf4nvf4.block_scale.scale_vec::4X.m16n8k64.row.col.f32.e2m1.e2m1.f32.ue4m3`.

## VERDICT (3-voice: Codex GPT-5.x high + Gemini 3.1 Pro high + Opus 4.8 high) — **GO, narrowly scoped**

**Unanimous GO on the narrow claim:** the NVFP4 block-scaled tensor-core MMA **instruction is available and
bit-correct for one tile on sm_121 at our current cubecl pin.** This **kills the plan's "NVFP4 tensor-core
blocked until a pin bump" assumption** — the prior NO-GO was only the bf16/f32 CMMA path; the E2M1 scaled path
was simply never launched.

**Unanimous caveat — this proves the instruction, NOT a usable GEMM.** All three: the probe loads global→
registers and **bypasses shared memory entirely**, so it proves nothing about the TMA/shared-mem staging +
K-loop pipeline that must fit in **99 KiB/block** — *exactly* the axis that sank TRT-LLM's CUTLASS NVFP4 to
~4.8 tok/s on SM121. Single-warp, single K-tile, no occupancy/throughput measured.

**Opus's load-bearing extra finding (confidence 8/10) — the two-call workaround may mask a bug.** The m16n8
accumulator's 4 f32 registers natively span all 16 rows (`cubecl/.../cuda/processors.rs:107-111`: i=0,1→rows
0-7, i=2,3→rows 8-15); the canonical `runtime_tests/cmma.rs:1216` stores all lines from **one** `execute_scaled`.
Our probe forces `line_size_c=1`, uses only 2 of 4 accumulator registers, **discards the registers holding rows
8-15, and runs a SECOND full MMA** (reloading A's lower rows + a different scale set) to recover them. Either
(a) the canonical single-call path is **broken on the e4m3/4X route** (the fp4 runtime test only covers
ue8m0/factor-2, so e4m3 bottom-half may never have been exercised) → the PASS only proves the top half, or
(b) it's a harmless-but-2×-wasteful double issue. **Must be resolved before any kernel leans on this.**

**Oracle caveats (Opus/Codex):** the host reference (`E2M1 * E4M3` per-16-block, f32 matmul) is faithful for
THIS config but: scale **sign is ignored** in PTX (`ue4m3`) while the host uses signed — untested (all probe
scales positive); inputs are **too clean** (quarter-integers, K=64 → exact f32, so `max_abs_diff=0` is
uninformative about real rounding/large-K reduction); the **per-tensor FP32 second-level scale** real NVFP4
checkpoints use is omitted.

## Plan implications (folded into QUANT_FLASH_SPEC_PLAN.md)
- Reframe NVFP4 prefill (M≫1) + MTP K-token verify (M=K) from **"blocked until pin bump"** → **"instruction
  available on the current pin; tiled-kernel + perf + canonical-path correctness UNPROVEN."** Not "adopt NVFP4."
- **Single-token decode stays SIMT** (bandwidth-bound; m16n8 wastes 15/16 of M at M=1). The decode=SIMT call holds.
- The "pin bump" upstream track is **demoted** — not needed for the NVFP4 instruction (still needed only for the
  bf16/f32 CMMA path, which we don't use for NVFP4).

## P0.3b — the next probe (the real de-risk; queued)
A single **tiled, multi-warp NVFP4 expert-GEMM** at a representative prefill shape (e.g. M=256 × N=inter × K=hidden):
1. **Natural 4-register accumulator, ONE `execute_scaled` per K-step, NO two-call workaround** — resolves the
   Opus item-2 question (is the canonical full-tile path correct on e4m3/4X?). If not → file a cubecl bug, downgrade GO.
2. **Shared-mem staging + double-buffer; print smem bytes used vs 99 KiB + achieved occupancy** (the TRT-LLM trap).
3. **K-loop accumulation** over full K (register-resident).
4. **Throughput (TFLOP/s or prefill tok/s) vs BOTH the bf16 tensor-core path AND the SIMT path** — a real GO
   requires beating bf16.
5. **Realistic numerics:** values that round in E2M1, ≥1 **negative** block scale (exercise sign-ignore), the
   per-tensor FP32 scale, large K (accumulation stress).
The single decisive number: **sustained TFLOP/s at an occupancy that fits 99 KiB, relative to bf16.**
