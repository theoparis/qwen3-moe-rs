# P0.2 spec — factor the CUDA-graph capture harness into a reusable `src/` helper

**Why:** The capture/replay *mechanism* (`ComputeClient::capture_arena(warmup, f) -> CapturedGraph`,
`.replay()`) is reused, but the *model-level harness* around it (persistent device buffers, prefill,
`reset_for_replay`, in-place writeback, VA-stability asserts, the per-token replay loop) is **hand-rolled and
near-duplicated** across `examples/cudagraph_pfinal_bench.rs`, `examples/cudagraph_moe_decode_bench.rs`, and is
needed again by `examples/vllm_infer.rs` (L2B) and the GRPO rollout (`src/grpo/rollout.rs:551` TODO). DRY: one
helper.

## Deliverable
`src/capture.rs` (new, `pub mod capture;` in `lib.rs`) — a reusable single-token captured-decode driver, plus a
refactor of `examples/cudagraph_moe_decode_bench.rs` to use it, proving **token-identical** output to the
pre-refactor bench (the regression gate).

## API sketch (raw `CubeBackend`, below Fusion)
```rust
/// Persistent device buffers a captured decode step reads/writes IN PLACE (VA must stay stable).
pub struct DecodeState<B: Backend> { tok: Tensor<B,2,Int>, pos: Tensor<B,1,Int>, last: Tensor<B,2>, finished: Tensor<B,1,Int>, /* + KV cache handle */ }

/// Build state once, capture one step, replay per token. `step` must: read tok/pos, run one
/// forward_with_cache_static_pre, write next tok+logits in place, advance pos in-graph. NO host sync.
pub struct CapturedDecoder { graph: CapturedGraph, state: DecodeState }

impl CapturedDecoder {
    /// warmup>=3 eager passes (JIT+autotune settle) then capture. Asserts every buffer's device VA is
    /// unchanged across capture (float_va/int_va snapshot+assert, per cudagraph_moe_decode_bench.rs:57-71,192-252).
    pub fn build(model, cache, warmup: usize, step: impl Fn(&DecodeState)) -> Self;
    pub fn reset_and_prefill(&mut self, prompt_ids: &[i64]);   // cache.reset_for_replay() + re-prefill
    pub fn decode_n(&mut self, n: usize, eos: &[i64]) -> Vec<i64>; // replay() per token, on-device argmax/sample, one D2H at end
}
```

## Hard constraints (from the 3-voice review — bake in as asserts/docs)
- **Raw `CubeBackend<CudaRuntime,...>`, not `Cuda=Fusion`** (capture is below Fusion).
- **No per-step host read inside the captured step** (on-device argmax/Gumbel via `src/sampling_device.rs` into
  the persistent `last`/`tok` buffers; one D2H after the whole replay loop).
- **VA-stability:** snapshot each persistent buffer's device pointer before capture, assert unchanged after
  (a stray `.clone()` relocates the VA → silent broken replay). Provide a `verify_va()` mutation-test hook.
- **`warmup < max_new`** guard (the warmup pass writes column `lp+warmup`).
- Buffers allocated OUTSIDE the captured region; updated in place via `Option::take()` + a single op.

## Tests / gate
- `examples/cudagraph_moe_decode_bench.rs` refactored onto `CapturedDecoder` is **token-identical** to its
  pre-refactor greedy output (the existing pass criterion) — this is a CRITICAL regression gate.
- A buffer-move mutation test: relocate a persistent buffer → replay must reflect it (proves VA binding).

## Build/run
`RUSTFLAGS="-C target-feature=+fp16" cargo build --release --features cuda --example cudagraph_moe_decode_bench`
then run; compare the emitted token string to the known-good baseline.
